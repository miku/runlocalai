## 3. Setup: Jan and our providers

A *provider* is a server that runs models and answers requests (OpenAI
compatible API). Jan is the client.

1. open Jan, go to **Settings > Model Providers**, click **+**
2. name it (e.g. "L"), paste **Base URL** and **API key** from your card
3. press **reload**, the list of models fills in
4. repeat for the other providers

## 4. Model tasting

Pick three models: a **small**, a **medium** and a **large** one, e.g.
`meta-llama-3.1-8b-instruct`, `qwen3.8-27b`, `qwen3.5-397b-a17b`. Send each the
same two prompts, each in a **New Chat**.

> **Prompt 1**, a useful task
>
> Rewrite in plain language, at most three short sentences: "Die
> Inanspruchnahme der Fernleihe setzt eine gültige Benutzungsberechtigung
> voraus, wobei die Bereitstellung der bestellten Medien unter dem Vorbehalt
> der Verfügbarkeit bei der gebenden Bibliothek erfolgt und etwaige anfallende
> Gebühren unabhängig vom Erfolg der Bestellung zu entrichten sind."

> **Prompt 2**, a trap
>
> Name three peer-reviewed papers on *[a niche topic from your field]*, with
> authors, year and DOI.

Check the DOIs at [doi.org](https://doi.org/): do they exist, and do they match?

> **Vote**: Which model would you use for prompt 1? Did any model say "I am not
> sure" on prompt 2?

Without tools, a model can only *remember*; we come back to that in part 7.

How to read a model name, e.g. `qwen3.5-122b-a10b`: family *qwen*, version
*3.5*, *122b* billion parameters in total, of which *a10b*, 10 billion, are
active per token (mixture of experts), so it runs faster than its size suggests.

## 5. From prompt to assistant

A *system prompt* holds standing instructions, sent along with every message.
In Jan, an **assistant** is a saved system prompt: **Settings > Assistants >
Add Assistant**.

Create two assistants:

> **Translator** (adapted from the TranslateGemma prompt, see April)
>
> You are a professional German to English translator. Convey meaning and
> nuance of the original, follow English grammar and conventions. Produce only
> the translation, without explanations.

> **Feedback, not rewrite**
>
> You give feedback on my text. List at most five concrete problems (grammar,
> logic, clarity), quote the passage for each and say why it is a problem.
> Never rewrite the text.

Now try your own paragraph:

1. in a plain chat, without assistant: "Improve this text: ..."
2. with the **Feedback** assistant, same paragraph
3. compare: which result still sounds like *you*?

> Significantly more heavy LLM users reported that the writing was less
> creative and not in their voice. [How LLMs Distort Our Written
> Language](https://arxiv.org/abs/2603.18161)

> **Discuss** (2 min, with your neighbour): What is a personal voice, and why
> does it matter?

## 6. Task cards

Work in pairs, pick one card (two if you are fast). Post your best and your
worst result to the pad.

### A. Messy data to a clean table

```
Standort;Monat;Ausleihen
Albertina;Jan 2026;1.234
BMN;2026-01;987
Campus;01/2026;1,1 Tsd.
Albertina;Februar 26;1310
BMN;2026-02;n/a
Campus;02/2026;1.05k
Albertina;2026/03;1 402
```

(fictional numbers)

> Turn this into a CSV with the columns location, month (YYYY-MM), loans
> (integer). Do not guess missing values, leave them empty. List every change
> you made.

Watch for: is `1.234` read as 1234? Does the model invent a value for `n/a`? Is
the list of changes complete?

Next step: "Write a Python script that does the same for a file with 10,000
rows." For larger data, let the model write the program, not do the work.

### B. A tiny tool, no install

> Write a single self-contained HTML file, no external libraries. I paste a
> list of DOIs, one per line. Show each as a clickable link to doi.org, mark
> duplicates and invalid lines, and show a count.

Save the answer as `doi.html` (in Notepad choose *Save as type: All files*) and
open it in your browser. If something breaks, describe what you see and paste
it back. Try `qwen3-coder-next` or `devstral-2-123b-instruct-2512`.

### C. Translate and check

Use your **Translator** assistant on a paragraph, e.g. from a library web page
or your own abstract. Then translate the result back, in a new chat, with a
different model.

Watch for: terminology (Fernleihe → *interlibrary loan*), shifts in meaning,
tone.

### D. A search strategy for your topic

> I research *[topic]*. Suggest a search strategy: key concepts, synonyms in
> English and German, and a Boolean query I can paste into BASE, OpenAlex or
> PubMed. Do not list any papers.

Run the query yourself. Compare with the DOI trap in part 4: here the model
builds the query, the database delivers the facts.

### E. Sparring partner

> Here is my claim: *[one or two sentences]*. Give me the three strongest
> counterarguments, and one question I should be able to answer.

Or: "Give me ten ideas for *[...]*, then pick the three most unusual and
explain why they might fail."

Watch for: generic or surprising? Does a larger model help?

## 7. Agents: models with tools

A chat model answers from what is in the conversation. An agent gets
**tools** and runs in a **loop**: it decides to read a file, search or run a
script, looks at the result, and continues until done.

```
you ──► model ──► tool call: read file, search, run script
          ▲                      │
          └────── result ◄───────┘    ... repeat until done
```

Three ingredients:

* a **model** trained for tool use (e.g. Qwen 3.x, GLM, gpt-oss, Devstral)
* a **harness** that offers the tools and runs the loop (Jan, pi, opencode, ...)
* **permissions**: what may it read, write, run? Files and web pages can contain
  instructions, too (prompt injection)

### Demo: DBIS26

[DBIS](https://dbis.ur.de/) lists research databases. All 14,708 records fit
in one 16MB JSONL file. No database, no vector index, no RAG: a generic agent,
an open model, shell tools (`grep`, `jq`) and a one-page prompt.
([details](https://github.com/ubleipzig/bibliocon-2026-595/tree/main/hacking/dbis))

> **Your input**: call out a research topic. The agent finds databases and
> their availability (open, national licence, licensed).

Same file, second question: "Write a short report about this dataset." The
agent writes and runs small scripts; a data analysis in a few minutes.

Optional: fixing the DOI trap. With a web tool, the agent asks
[OpenAlex](https://openalex.org/) and returns papers that exist.

### Outlook: skills

A *skill* is a folder with instructions (`SKILL.md`) and optional scripts that
an agent loads when needed. Example: "find a database in DBIS" as a skill, or
an `llms.txt` for Leipzig University Library, so that any agent can check
availability.
